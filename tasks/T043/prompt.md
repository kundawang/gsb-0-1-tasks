图书馆的自助取书柜（就是那种一排格子）要个后台逻辑：预约先把格子占上，取完释放，超时自动回收。

模型（data/lockers.json 是柜子清单，samples/requests.json 是预约/取书事件）：

- 柜子：格号 G01…，每格有尺寸（small/medium/large），一格同时只能放一个预约
- 预约：请求一本书（book_id），系统挑一个**能放下该书最小尺寸**的空格（同尺寸里取格号最小的）；
  没有合适空格就进等待队列，先进先出
- 取书：柜门打开 → 该格标记 occupied → 用户在 retention_hours（默认 48 小时）内取走 → 释放格子
- 超时：超过保留时长未取 → 标记 expired，格子释放，并把该书退回书架（事件记录）；
  若有人在等同类尺寸的格子，立刻按队列顺序分配
- 用户操作要幂等：同一个 book_id 重复"取书"请求只生效一次（返回已有柜号，不重复分配）

要做的：

1. 纯逻辑：`apply(events)` 回放事件，输出每步的柜位状态、等待队列、每个请求的生命周期（预约→占用→取走/过期）。
2. 分配规则必须稳定：尺寸匹配优先，其次格号最小；等待队列按 FIFO，同尺寸优先。
3. 边界：所有格占用满、预约的书不存在、同一用户并发预约两本书、超时后再次用同一 book_id 预约。
4. 输出统计：格子利用率、平均占用时长、过期率、被退回书架的书清单。

界面：柜位格子图（空/占用/过期回收 三色）+ 等待队列 + 事件日志。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写状态机与事件格式。

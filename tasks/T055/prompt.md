车间只有一条线，工单老拖期，想做个排产小工具：给定工单，排顺序、算延误，还能比较两种排法。

模型（samples/jobs.json 是工单，data/setup_matrix.json 是换型时间矩阵）：

- 工单：job_id、产品型号、数量、加工节拍（分钟/件）、交期（第 N 天结束）、释放时间（第 N 天开始可做）
- 换型：同型号之间不需要换型；不同型号按矩阵花 0~60 分钟
- 一天按 480 分钟有效工时计；当日做不完的顺延到第二天（不加班）

要做的：

1. 两种排法都实现并对比：
   - edd：按交期先后（并列按释放时间 → job_id）
   - setup_min：贪心减少换型（先按型号分组，组间用矩阵里换型时间最小的邻接顺序）
2. 输出每种排法的：加工顺序（含起始/结束时间，精确到分钟）、每单延误天数、总完工时间、
   总换型时间、按期率；两者对比表。
3. 计算口径写死：[start, end) 半开；换型时间算在工单开始之前；一天最多 480 分钟；
   跨天时剩余时间留到第二天（顺序不变）。
4. 边界：工单数量为 0、交期早于释放时间（标记为 impossible 并说明）、
   单件节拍 × 数量 > 一天工时（要拆天）、换型矩阵缺项（按同型处理并记录警告）。
5. 确定性：同一份输入跑两次结果一致（两种排法的顺序与时间逐分钟一致）。

界面：甘特图（按天分列，工单色块 + 换型小段）+ 对比表 + 延误明细。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写两种排法与计算口径。

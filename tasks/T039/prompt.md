我们店里的排班一直手排，容易出错，想做个生成器：给员工、班次规则和需求，排出一周的班表，还能校验。

输入（data/shift-rules.json + samples/staff.json）：

- 员工：id、姓名、可上班次（早/中/晚）、每周最多班次数、是否可连班、偏好（可选）
- 每天需求：早班需要几人、中班几人、晚班几人（周一到周日可以不同）
- 规则：
  - 一天最多一班（同一员工同一天不能上两个班次）
  - 晚班后第二天不能排早班（休息不足）
  - 连续上班天数不超过 max_consecutive_days（默认 5）
  - 每周班次数不超过员工上限
  - 员工只能上自己可上的班次

要做的：

1. 生成器：给 seed，排出满足需求的班表；排不出来时给出**具体缺口**（哪天哪个班缺几人，
   以及在现有约束下为什么排不出，比如"可用员工只有 2 人但早班需要 3 人"）。
2. 校验器：对任意一份班表（包括手工改过的）逐条检查上面 5 条规则，输出违规清单（员工、日期、班次、规则名）。
3. 公平性：输出每个员工的班次数分布（早/中/晚分别计数）和"最忙与最闲差几个班"；
   生成算法要尽量均衡（差 ≤ 1 最好，做不到要说明原因）。
4. 导出：CSV（行=员工，列=周一到周日，格子=班次或空）和 JSON（含统计与校验结果）。

硬指标：

1. 生成与校验都是纯逻辑，`node --test` 里直接测；排班结果必须只依赖 seed + 输入（同 seed 完全一致）。
2. 校验器要有"故意违规"的测试：手工改出晚班接早班、超过最大连班、超出员工上限三类，断言都被检出。
3. 排不出来时不能死循环：给一个必然失败的输入（比如早班需要 5 人但只有 3 个员工），
   要在 2 秒内返回缺口报告。
4. 边界：员工数为 0、需求全为 0、只有 1 个员工、全部员工都不接受晚班。
5. 输出里所有计数都是整数；日期用 ISO（2026-06-01）格式，周一为一周第一天。

界面：一个是可编辑的班表网格（拖拽或下拉选班次，改完立刻重新校验），一个是统计面板（分布、缺口、违规）。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写规则清单与缺口报告格式。

健身房洗衣房那种排队叫号，现在靠喊，想做个叫号系统：取号、叫号、过号重排、窗口分配都要有规矩。

规则（samples/queue_events.json 是一段时间内的事件序列）：

- 取号：拿到号码（当天 001 起递增），同时记录业务类型（普通/加急）与预计服务时长
- 窗口：3 个窗口；叫号时把队首的号分配给空闲窗口，窗口服务时长 = 该号的预计时长
- 优先级：加急号插到队首之后（同级别按取号顺序），但不能让普通号等超过 30 分钟 —— 触发时改为
  "普通号优先一轮"，规则要写清楚并能复现
- 过号：叫号 3 次（每次间隔 1 分钟）仍未到 → 标记过号并放到队尾（保留原序号，标记 missed 次数）
- 统计：每个号的等待时长、服务时长、是否过号；每个窗口的空闲时长；整体平均/最大等待

要做的：

1. 纯逻辑：喂事件序列（取号/到达窗口/服务完成/叫号超时）→ 输出每个时间点各窗口状态与队列快照，
   以及最终统计。时间用整数分钟，从 0 开始。
2. 事件要能按时间顺序回放；同一时刻多个事件按"服务完成 → 到达 → 取号 → 叫号"的固定顺序处理（写进 README）。
3. 边界：队列为空时叫号（空转不报错）、同一号重复到达、窗口服务时长为 0、过号后再次到达且窗口忙。
4. 确定性：同一份事件序列跑两次，队列快照与统计完全一致。

界面：三个窗口卡片（当前号/剩余时长）+ 队列列表（含过号标记）+ 统计条；可以按分钟步进或直接快进。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写规则与事件格式。

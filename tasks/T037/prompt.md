想做个迷宫小工具，给同事摸鱼用：给个种子和一份配置，生成迷宫、算最短路，还要能验证生成的迷宫是合法的。

配置项：宽 w、高 h（格）、额外连通度 extra_links（打通多少条额外通道）、起点、终点、seed。
- 迷宫必须是"完美迷宫"（连通且无环）再加 extra_links 条额外通道（这些通道会造出环，是有意的）
- 生成必须只依赖 seed：同 seed + 同配置 → 一模一样的地图（墙的集合完全一致）

要做的：

1. 生成器：从 seed 派生随机数（自己写个 xorshift/LCG 都行，不许用 Math.random），用随机化 DFS 或 Prim 生成。
2. 校验器：验证生成结果 —— 全格可达、完美迷宫阶段无环、额外通道数量正确、边界墙完整；
   校验要能对**任意**迷宫（包括我手工改过的）给出结论和第一个不满足的位置。
3. 求解器：A* 或 BFS 求 (起点 → 终点) 最短路，输出路径（格子序列）和步数；
   带环的迷宫也要能解（最短路唯一性不要求，但步数必须最小）。
4. 难度参数：`openness`（0~1，控制额外通道数量）。同一 seed 下 openness 越大，最短步数应该越小 ——
   测试里用 5 个 seed 验证这个单调趋势（允许并列，不许反向）。

硬指标：

1. 生成/校验/求解都是纯逻辑，`node --test` 里能直接测；建议把迷宫用 `Uint8Array` 或紧凑字符串表示，
   导出/导入的字符串格式要在 README 里写清楚（同 seed 生成同一个字符串）。
2. 大迷宫要能跑：100×100 生成 + 求解在 1 秒内完成（测试里给个宽松上限即可，别无限循环）。
3. 边界：宽或高为 1、起点等于终点、extra_links 超过格子数、非法 seed，各自明确行为。
4. 校验器对"被破坏的迷宫"要检出并给位置（测试里手工破坏一条边界墙，断言检出）。

界面：canvas 画迷宫（墙/路径/额外通道不同颜色），工具栏能改 seed 和参数、显示最短步数和校验结论；
加个"一步一步走"的按钮。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。

大棚的温湿度控制现在是人工开关，想做成规则联动：什么条件开风机/遮阳/加湿，什么时候关，要有滞回，别抖。

模型（data/devices.json 是设备清单，samples/readings.json 是一个下午的温湿度序列）：

- 设备：fan（风机）、shade（遮阳帘）、humidifier（加湿）、heater（加热）——
  每个设备有额定功率、启动延迟（秒）、最小运行时长（分钟）、最小间隔（分钟）
- 触发规则：
  - 温度 ≥ 30℃ 开风机；≤ 27℃ 关（滞回 3℃）；≥ 33℃ 同时开遮阳；≤ 30℃ 收遮阳
  - 湿度 ≤ 45% 开加湿；≥ 52% 关（滞回 7%）
  - 温度 ≤ 12℃ 开加热；≥ 15℃ 关
  - 冲突规则：加热与风机不能同时开 → 优先保持温度（先关风机、延迟 60 秒后再开加热）
- 记录：每次开关都要有原因（命中的规则）、当时的温湿度、以及被延迟/被抑制的设备

要做的：

1. 纯逻辑：run(readings, devices, rules) → 时间线事件（每个 tick 的设备状态 + 决策原因）与汇总
   （各设备运行率、总耗电 kWh、被抑制次数）。
2. 滞回与最小运行/间隔必须严格生效：测试里构造 28→31→28 的抖动序列，断言风机不会反复启停。
3. 边界：温度缺失、设备故障（手动标记 unavailable）、同一 tick 命中多条冲突规则、序列只有 1 个点。
4. 决策顺序写死：先算传感器报警 → 再按优先级（安全 > 温度 > 湿度）取动作 → 再套最小运行/间隔与延迟。
5. 确定性：同一份序列跑两次，事件时间线完全一致。

界面：设备状态面板（开/关 + 已运行时长）+ 温湿度曲线（带阈值线）+ 事件日志（可读原因）。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写规则优先级与滞回口径。

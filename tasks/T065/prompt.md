想做个纸牌接龙（Klondike）的可解性工具：给 seed 发牌，判断这局能不能赢，能赢就给出一串可复现的走法。

要做的：

1. 发牌：标准 Klondike（1 副 52 张，7 列，第 i 列 i 张，只有每列最后一张翻开；剩余 24 张在牌堆），
   洗牌必须只用 seed（自己写随机数，不许用 Math.random），同 seed 必须发出同一局。
2. 求解器：搜索可解性，输出：
   - `solvable: true/false`
   - 如果可解：走法序列（每步是 {type, from, to}，类型有 draw / move / to_foundation），
     走法要能被复现器按顺序重放并达到"四堆花色齐全"的终局
   - 搜索统计：访问过的状态数、用时（毫秒）
3. 正确性要求（写死）：
   - 只有 K 能放到空列；列内必须交替颜色且降序；基础堆（foundation）必须同花且升序从 A 开始
   - 每次只能移动一张（不实现"整列搬运"也行，但要在 README 里说明这一简化）
   - 复现器必须校验每一步合法，非法就报错并指出第几步
4. 搜索要有上限：单局最多访问 200000 个状态；超过就返回 `unknown`（说明是超时不是无解），
   并且用时上限 3 秒（测试里给宽松阈值）。
5. 统计：跑 20 个 seed 的可解率，以及"可解的局平均走了多少步"。

界面：牌桌渲染（列/牌堆/基础堆）+ seed 输入 + 求解按钮 + 走法列表（点某步跳到该步状态）。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写规则简化点与搜索上限。

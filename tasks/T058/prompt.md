搅拌站想省钱：在满足强度和塌落度要求的前提下，从可选配方里挑最便宜的，并给出满足性证明。

模型（data/materials.json 是原料价格与参数，data/recipes.json 是候选配方，samples/orders.json 是订单要求）：

- 原料：水泥（元/kg 与强度贡献系数）、砂、石、水、外加剂（减水率、单价）、粉煤灰（取代系数）
- 配方：各原料用量（kg/m³）、实测强度（MPa）、实测塌落度（mm）、单价（元/m³）
- 要求：目标强度 ≥ 设计强度 + 富余（默认 +5MPa）、塌落度在下限与上限之间、
  塌落度每偏差 10mm 折价或加价（简化成线性调整，系数写在配置里）

要做的：

1. 纯逻辑：evaluate(order, recipe) → 是否满足（逐条给结论与偏差）、调整后成本；
   choose(order, recipes, materials) → 满足约束里最便宜的方案 + 为什么其他方案不选（逐条列原因）。
2. 成本口径写死：原材料成本 + 外加剂成本 + 调整项（强度不足直接判不满足，不参与比价）；
   金额用分（整数），单价用元/m³ 但内部按分算。
3. 还要支持允许微调模式：粉煤灰最多取代水泥 20%（强度按取代系数折算），
   在这个约束下重新算最低成本方案；两种模式（原样比价 / 允许微调）都要给出结果与差值。
4. 边界：没有满足约束的配方（输出最接近的 3 个并给出差在哪）、订单强度极高、
   配方里出现未知原料、同价并列时按强度更高的选。
5. 确定性：同一输入跑两次结果一致。

界面：原料价格表 + 候选列表（满足/不满足、成本、偏差）+ 推荐方案卡片（含满足性逐条证明）+ 导出报价单。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写成本口径与折算系数。

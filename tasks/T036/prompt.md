我们小店的结算逻辑现在手算，经常算错运费和优惠，想做成一个能复算的模块 + 一个结账页面。

规则（data/pricing.json 里是费率表，samples/carts.json 是几个购物车样例）：

1. 商品：sku/单价/数量/是否大件（oversize）。小计 = 单价 × 数量，单位是分（整数），不要用浮点存钱。
2. 运费：
   - 基础运费 8 元；订单满 99 元免基础运费
   - 大件每件加 15 元
   - 偏远地区（region 字段）额外加 12 元
   - 冷链商品（cold: true）额外加 6 元
   运费按"先算加项、再判免基础"的顺序来（免的只是那 8 元，加项照收）。
3. 优惠券（一个订单最多用两张，一张折扣券 + 一张满减券）：
   - 折扣券：按百分比打折，作用范围可以是"整车"或"指定 sku 列表"，作用于商品小计（不含运费）
   - 满减券：满 X 减 Y，按商品小计判定
   - 两张券作用顺序：先折扣后满减；折扣后金额出现小数要四舍五入到分（使用银行家舍入，写清楚）
   - 券的适用范围重叠时，折扣按 sku 分摊到每个商品，分摊后每个商品的折后价用整数分表示，
     分摊产生的尾差按"单价从高到低"依次补齐，保证分摊之和等于总折扣
4. 输出：商品明细（原价/折后价/折扣分摊额）、商品小计、运费明细、优惠明细、应付总额。
   所有金额用分（整数）输出，同时给一个格式化好的 `¥12.34` 字符串。

硬指标：

1. 结算是纯函数：`settle(cart, coupons, region)` → 结果对象，`node --test` 里直接测。
2. 尾差分摊必须有测试：构造一个 3 件商品、折扣除不尽的购物车，断言分摊之和 == 总折扣，且每件折后价 ≥ 0。
3. 边界：空购物车、券不满足门槛、券指定了不存在的 sku、折扣券 100%、满减减到 0 以下
   （应付不能为负，超出部分要记录"未使用额度"）、同一张券重复使用（要拒绝）。
4. 任何金额都不允许出现浮点误差：测试里断言 `Number.isInteger`。

界面：左边购物车（可改数量、加/删券），右边实时结账明细；改数量或券立刻重算。
约束：原生 ES module + HTML/CSS，不引依赖、不联网。README 写清规则顺序、舍入规则、券的约束。

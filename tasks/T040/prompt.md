我们几个人的笔记文件经常各改各的，合并全靠人眼。想做个网页版三路合并工具：给基线版、我方版、对方版，
给出合并结果和冲突清单。

输入：三段文本（samples/ 里有 base.txt / local.txt / remote.txt 这个样例，是一个被两边同时改过的清单）。

要做的：

1. 行级三路合并（类似 diff3）：
   - 只有一边改 → 直接采用
   - 两边改成一样 → 采用该结果，不算冲突
   - 两边都改且不同 → 冲突，输出冲突块（我方/对方各自的内容）
   - 一边删一边改 → 冲突（删除 vs 修改）
2. 输出：
   - 合并后的文本（冲突块用 `<<<<<<< 我方` / `=======` / `>>>>>>> 对方` 包裹）
   - 冲突清单：块序号、基线行号范围、我方行号范围、对方行号范围、双方行数
   - 两侧变更统计：新增/删除/修改各多少行
3. 交互：三栏展示（我方 / 合并结果 / 对方），冲突块高亮，能逐块选择"用我方/用对方/两个都要"，
   选完立刻更新合并结果和剩余冲突数。选择操作要能撤销（至少 20 步）。

硬指标：

1. 合并算法是纯函数（base/local/remote → {merged_text, conflicts, stats}），`node --test` 里直接测。
2. 测试必须覆盖：只在一边改、两边同改、两边改成一样、一边删除一边修改、连续多个冲突块、
   行尾空格差异（要算"修改"，不能忽略）、末尾缺换行。
3. 同一份输入跑两次结果完全一致（冲突块顺序、行号都一致）。
4. 大输入：三方各 5000 行的清单要在 2 秒内出结果；不许用 O(n²) 逐行比较（测试里给宽松时间上限）。
5. 空文件、三方完全相同、只有 base 为空（新增文件）这几种情况要有确定行为。

界面细节：三栏等宽、行号对齐；冲突块可折叠；底部状态栏显示"共 N 个冲突，剩 M 个未处理"。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写冲突判定规则与行号口径。

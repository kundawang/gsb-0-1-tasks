想给自制的卡牌桌游做个效果结算引擎：一堆牌互相触发的时候，顺序不能乱，还得能复盘。

模型（data/cards.json 是牌的定义，samples/events.json 是一段出牌/触发事件）：

- 牌：id、名称、类型（法术/随从）、触发时机（on_play / on_death / on_turn_start / on_damage）、
  效果列表（damage 3、heal 2、draw 1、buff +1/+1、summon、destroy）
- 触发规则（写死）：
  1. 一张牌打出后，先结算它自身的 on_play 效果，再结算场上其他牌的触发（按入场顺序）
  2. 效果可以产生新事件（比如 damage 导致 on_damage 触发），新事件进入"待结算队列"，
     当前效果结算完再处理（像堆叠栈）
  3. 同一时机多个触发按牌的入场顺序（先进先出）；同名牌按入场顺序，不按 id
  4. 一个效果结算完要写日志：谁触发的、什么效果、对谁、数值变化、剩余生命

要做的：

1. 纯逻辑：`apply(state, events)` → 最终状态 + 完整日志（可重放）；
   `replay(log)` → 从初始状态重放日志得到相同最终状态（测试断言两者一致）。
2. 状态：玩家生命、场上随从（每张有生命/攻击/入场序号）、手牌数、牌库数。
3. 边界：随从生命降到 0 立即进"待死亡队列"（等当前效果结算完再依次 on_death）、
   无限循环保护（同一效果链超过 50 次就中断并记录）、对已死亡随从的效果判为无效并记录、
   牌库里没牌还抽牌（记录"疲劳"并扣血）。
4. 输出统计：每个时机触发次数、总伤害/总治疗、最强combo（连续触发的最大长度）。
5. 确定性：同一份事件跑两次，日志逐行一致。

界面：牌桌（双方随从/血线）+ 事件日志（可逐条步进）+ 触发链路树形展示。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写结算顺序与队列规则。

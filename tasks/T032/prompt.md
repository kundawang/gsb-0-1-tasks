我们仓库拣货现在全靠人凭经验走，想做个排程小工具先把路径算明白：给一张货位图和一批订单，
算出每个波次怎么走、走多远，再和"按订单顺序瞎走"比一比差多少。

数据（data/warehouse.json、samples/orders.json 里给了样例）：

- 仓库是网格：宽 w、高 h（格），出入口在 (0,0)；货位有 id 和坐标 (x,y)，一个货位放一种 SKU
- 订单：order_id + 若干 SKU 行（sku、qty）
- 波次容量：一个波次最多装 max_items 件、最多 pick_list_size 个不同货位（工具里这两个是参数）

要算的：

1. 按给定顺序把订单拆成波次：一个订单不能拆到两个波次；放不下就开新波次（装箱时按订单里 SKU 出现顺序处理）。
2. 每个波次内部的拣货路径：从 (0,0) 出发、遍历该波次所有货位、回到 (0,0)。
   提供两种策略并对比：a) 按货位 id 字典序；b) 最近邻（并列时取坐标 (x,y) 更小的）。
   距离用曼哈顿距离。
3. 输出每个波次的：订单列表、货位访问顺序、路径长度、装了几件；再给整体汇总
   （波次数、总距离、平均每件距离、与字典序策略相比省了百分之多少，保留 1 位小数）。
4. 边界：空订单、空货位、订单引用不存在的 SKU、波次容量小于单个订单所需货位数 —— 各自给出明确行为
   （能走完就走，走不完就在结果里标 unfulfillable 并说明原因，别静默丢）。

硬指标：

1. 纯逻辑（拆波次、两种路径、汇总）必须能脱离界面单测；`node --test` 或 `python -m pytest -q` 都行，
   看你在 starter 里选的语言（starter 是空的纯 JS 目录，你可以只用标准库）。
2. 同一份输入 + 同一组参数，输出必须完全一致（不许用 Math.random，不许依赖 Set/Map 遍历顺序）。
3. 路径长度、件数、百分比这些数值要能对上：测试里至少覆盖"一个订单刚好装满""跨波次边界""并列最近邻"。

界面：左边 SVG 画货位和路径（不同波次不同颜色），右边表格列每个波次明细 + 汇总；给个参数面板调容量。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写怎么跑、怎么测、参数含义。

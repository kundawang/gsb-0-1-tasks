我们水厂想做个"疑似漏损管段"的辅助定位工具：拿几个监测点的流量和压力读数，按规则推一下哪段可能漏了。

模型（data/network.json 是管段拓扑，samples/readings.json 是各监测点的读数序列）：

- 管网：节点 + 管段（段有长度、口径、上下游节点）；每个节点可能有流量计/压力表
- 读数：每个监测点每个小时一组 {flow, pressure}
- 规则（就用这些，别搞水力模型）：
  1. 夜间最小流量（00:00-04:00 的平均流量）比前 7 天同期均值高出 15% 以上 → 标记该分区"疑似漏损"
  2. 某监测点压力比上游监测点压力下降超过 0.15MPa，且两段之间没有其他监测点 → 该两段纳入候选
  3. 同一分区连续 3 天命中规则 1 → 置信度从 low 提升到 high
- 输出：候选管段列表（排序：命中规则数 → 管段长度）、置信度、命中依据（哪条规则、哪天的哪个值）

要做的：

1. 纯逻辑：`detect(network, readings)` → { candidates: [...], notes: [...] }；全部可单测。
2. 缺失数据处理：某小时缺测 → 用同一天该点的中位数补；整天缺测 → 该天不参与均值并记录说明。
3. 边界：读数只够 3 天、所有点流量相同、压力读数为 0（仪表故障，要单独标记不要参与规则 2）。
4. 输出要能人工复核：每条候选都要给出原始读数值（比如"节点N3 夜均 12.4L/s，7 天均值 10.1L/s，+22.8%"）。

界面：管网简图（节点/管段，候选段高亮）+ 候选列表（含依据）+ 趋势小图。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写规则与置信度含义。

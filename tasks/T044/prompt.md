咖啡店早上出杯太乱，经理要一个"出杯序列"工具：给订单队列，按饮品类别安排并行出杯，算出预计完成时间。

模型（samples/orders.json 是半小时的订单样例）：

- 订单：order_id、下单时间（分钟）、若干饮品（类型 + 数量），饮品类型：espresso（2 分钟/杯）、
  milk（3 分钟）、tea（1 分钟）、cold（1 分钟）；冷饮和热饮可以并行（两条产线），同类饮品串行
- 两台机器：热饮线（espresso/milk/tea）、冷饮线（cold）；每条线同时只能做一杯
- 插单：加急订单（priority=express）插到该线队首，但已经在做的那杯不打断
- 完成时间：一单里所有饮品都做完才算完成；输出每单完成时间、等待时长、以及每条线的时段利用率

要做的：

1. 纯逻辑：`simulate(orders, config)` → 每条线的执行序列（时间段 + 饮品）、每单完成时间、统计。
2. 排序：同一时刻多个订单，先按 priority（express 优先），再按下单时间，再按 order_id（稳定）。
3. 边界：订单里 0 杯、同单里 3 杯 espresso（要串行）、下单时间倒序、两条线都空闲时同时开工。
4. 边界处取处理顺序要写死：同一分钟内"完成 → 下单 → 插单"。
5. 确定性：同一份订单跑两次，执行序列与完成时间完全一致。

界面：时间轴（两条线各一条泳道，色块表示饮品）+ 订单列表（完成时间/等待）+ 利用率统计。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写时长表与模拟步进规则。

园区充电桩不够用，想做个调度 + 计费的小系统：排队、共享功率、峰谷电价都要算清楚。

模型（data/chargers.json 是桩与总功率，samples/arrivals.json 是到达/离开事件）：

- 4 个桩，共享总功率 120kW；同时充电的车平分功率，但每辆不超过自己请求的功率（请求 7/11/22/60kW）
- 排队：到达时没空桩就排队（FIFO）；有空桩且"总功率还没满"就立刻开始充
- 充电：按分钟结算，电量 = 实际功率 × 时间；车的电池 60kWh，充到 100% 自动断开（后续时间不再计费）
- 电价：峰段（10:00-12:00、18:00-21:00）1.2 元/kWh；平段 0.9；谷段（23:00-07:00）0.5
- 计费按分钟段累加（跨时段要拆），金额用分（整数）

要做的：

1. 纯逻辑：`simulate(events, config)` → 每个桩的充电时间线、每辆车的电量/费用明细（按时段拆）、
   排队时长、总功率利用率。
2. 功率分配规则写死：同时 N 辆平分总功率，再对超过请求值的部分回收，回收的功率二次分配给
   还没满请求的车（迭代到稳定）；测试里覆盖 3 辆 60kW 车同时到达的情况。
3. 边界：电池已满的车到达、同一辆车重复到达、离场时未充满（按实充电量计费）、跨天充电。
4. 确定性：同一份事件序列跑两次，时间线与费用完全一致；金额断言为整数分。

界面：功率仪表（总功率 + 每桩功率实时条）、车列表（剩余电量/已花费用）、排队区。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写功率分配与计费规则。

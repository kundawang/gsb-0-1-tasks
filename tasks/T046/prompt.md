公司会议室老撞车，想做个预订检查工具：能不能订、和谁撞了、周期会议怎么展开，都要说清楚。

模型（samples/bookings.json 是已有预订，data/rooms.json 是会议室与容量）：

- 会议室：id、名称、容量、是否允许跨午休
- 预订：room_id、日期、开始时间、结束时间、组织者、参会人、是否周期（daily/weekly）
- 缓冲时间：每个会议室有 buffer_minutes（默认 10），两场之间要留出缓冲（前一场结束 + buffer ≤ 后一场开始）
- 周期展开：weekly 要展开到指定结束日期（含），遇到周末跳过（可配置）

要做的：

1. 纯逻辑：
   - `expand(booking)` → 展开后的单场次列表（周期 + 跳过规则）
   - `check(roomId, slot)` → 是否可订 + 冲突列表（每条的 id、时间、组织者、重叠分钟数）
   - `suggest(roomId, slot, rooms)` → 同一时段里可用的其他会议室（按容量升序）
2. 冲突判定要包含缓冲时间：`[start, end)` 半开区间 + buffer；结束时间等于下一场开始时间仍算冲突（因为缓冲）。
3. 边界：结束早于开始、跨天、周期会议展开超过 1 年、参会人数超过容量（要警告但不算冲突）。
4. 输出：按天生成的占用时间线（便于人工核对）+ 冲突统计。

界面：周视图网格（点格子发起预订，冲突格高亮并弹出冲突明细），右侧显示可用会议室建议。
约束：原生 ES module + HTML/CSS，不引依赖、不联网、不构建。README 写缓冲与周期展开规则。
